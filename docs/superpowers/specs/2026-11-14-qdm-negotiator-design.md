# QDM Negotiator — Design

วันที่: 2026-11-14
สถานะ: รออนุมัติ

## 1. เป้าหมายและเหตุผล

Web app หน้าเดียวสำหรับนำเสนอในห้องเรียนวิชา OM บนคอมพิวเตอร์ เปิดผ่านเว็บไซต์
แอปใช้แค่ EOQ และ Quantity Discount Model (QDM) เพื่อตอบคำถาม 3 ข้อ:

1. ในตารางส่วนลดที่ร้านเสนอ ควรสั่งครั้งละเท่าไร และมีจุดที่ดีกว่าคำตอบในสไลด์ (1,000 ชิ้น) หรือไม่
2. ถ้าจะต่อรอง ควรขอราคาเท่าไรที่ล็อตขนาดไหน จึงจะได้ TC ต่ำกว่าข้อเสนอที่ดีที่สุดของร้าน
3. ข้อเสนอต่อรองนั้นช่วยให้ไม่ต้องสั่งล็อตใหญ่เกินจำเป็นได้แค่ไหน (ขนาดล็อต จำนวนครั้งที่สั่ง สต็อกเฉลี่ย)

ผู้ใช้ปรับสมมติฐานทุกตัวได้ และกราฟกับผลลัพธ์เปลี่ยนตามทันที

### Goals
- คำนวณ QDM ตามขั้นตอนในสไลด์ และได้ตัวเลขตรงกับสไลด์ 50–52
- แสดง "ราคาเท่าทุน" ของทุกขนาดล็อต เพื่อใช้เป็นตัวเลขต่อรอง
- ให้ผู้ใช้ลองข้อเสนอต่อรอง (ล็อต, ราคา) แล้วเห็น TC ใหม่และส่วนต่างทันที
- input ทุกตัวแก้ได้ รวมถึงตารางส่วนลด และค่าที่แก้ติดไปกับลิงก์
- หน้าจออ่านง่ายเมื่อฉายโปรเจกเตอร์ ใช้ง่าย ดูทันสมัย
- deploy ด้วย GitHub Pages

### Non-goals
- Safety stock, reorder point, ความไม่แน่นอนของ demand
- โมเดลต้นทุนฝั่งผู้ขาย หรือการคำนวณ bullwhip effect
- สินค้าหลายรายการ, บัญชีผู้ใช้, ฐานข้อมูล, backend
- Export PDF, สลับภาษา, dark mode, tooltip ตามเมาส์บนกราฟ
- การออกแบบสำหรับมือถือเป็นหลัก (ต้องเปิดได้ แต่ไม่ใช่เป้าหมาย)

### Anti-goals
- ตัวเลขไม่ตรงกับสไลด์ของอาจารย์
- แอปแนะนำให้สั่งล็อตใหญ่ขึ้นโดยไม่มีเหตุผลด้าน TC
- กราฟกระตุกเมื่อเลื่อน slider
- ต้องติดตั้งโปรแกรม หรือมีขั้นตอน build ที่พังได้ก่อนนำเสนอ

## 4. โมเดลคำนวณ

### ตัวแปร
- `D` ความต้องการต่อปี (หน่วย/ปี)
- `S` ค่าสั่งซื้อต่อครั้ง (฿/ครั้ง)
- `I` อัตราค่าเก็บรักษาต่อปี เป็นสัดส่วนของราคาสินค้า
- ตารางส่วนลด: รายการของ `{minQty, price}` เรียงตาม `minQty` จากน้อยไปมาก
  ช่วงแรกมี `minQty = 0` เสมอ ขอบบนของช่วง i คือ `minQty` ของช่วงถัดไป ลบ 1 ช่วงสุดท้ายไม่มีขอบบน

### สูตร
- ต้นทุนรวมต่อปี: `TC(Q, P) = D·P + (D/Q)·S + (Q/2)·I·P`
- EOQ ที่ราคา P: `Q*(P) = √(2DS / (I·P))`
- ราคาเท่าทุนที่ล็อต Q: `P_be(Q) = (TC_best − (D/Q)·S) / (D + Q·I/2)`
  คือราคาสูงสุดที่ทำให้ `TC(Q, P)` ไม่เกิน `TC_best`

### ขั้นตอน QDM (ตามสไลด์)
สำหรับแต่ละช่วงราคา:
1. คำนวณ `Q*(P_i)` แล้วปัดเป็นจำนวนเต็มที่ใกล้ที่สุด
2. จัดสถานะ:
   - `feasible`: อยู่ในช่วง ใช้ค่านั้น
   - `adjusted`: ต่ำกว่าช่วง ปัดขึ้นเป็น `minQty` ของช่วง
   - `discarded`: สูงกว่าขอบบนของช่วง ตัดทิ้ง ไม่นำไปเปรียบเทียบ
3. คำนวณ TC ที่ปริมาณหลังปรับ

`TC_best` คือ TC ต่ำสุดในบรรดาช่วงที่ไม่ถูกตัดทิ้ง เรียกจุดนี้ว่า "ข้อเสนอที่ดีที่สุดของร้าน"

### ข้อเสนอต่อรอง
ผู้ใช้กำหนด `Qn` (จำนวนเต็ม) และ `Pn` แอปคำนวณ:
- `TC_n = TC(Qn, Pn)` แยกเป็นค่าสินค้า ค่าสั่งซื้อ ค่าเก็บรักษา
- เงินที่ประหยัดต่อปี = `TC_best − TC_n` (ค่าลบแปลว่าแพงกว่าข้อเสนอของร้าน)
- จำนวนครั้งที่สั่งต่อปี = `D / Qn` และระยะห่างระหว่างการสั่ง = `365·Qn / D` วัน
- สต็อกเฉลี่ย = `Qn / 2` เทียบกับสต็อกเฉลี่ยของข้อเสนอที่ดีที่สุดของร้าน
- ราคาเท่าทุนที่ล็อตนี้ = `P_be(Qn)` ถ้าค่าไม่เป็นบวก แสดง "ไม่มีราคาที่คุ้มที่ล็อตนี้"

ค่าแนะนำของข้อเสนอต่อรอง: `Pn` = ราคาของข้อเสนอที่ดีที่สุดของร้าน และ `Qn` = `Q*(Pn)` ปัดเป็นจำนวนเต็ม
เหตุผล: เป็นข้อเสนอ "ขอราคาเดิม แต่สั่งล็อตที่เหมาะกับเรา" ซึ่งตรงกับประเด็นที่ต้องการนำเสนอ
แอปใช้ค่าแนะนำเมื่อเปิดครั้งแรก และเมื่อกดปุ่ม "ใช้ค่าแนะนำ"
หลังจากนั้นค่า `Qn`, `Pn` ที่ผู้ใช้ตั้งจะคงอยู่แม้เปลี่ยนสมมติฐานอื่น

### ตัวเลขอ้างอิง (โจทย์ Bee Beauty: D = 5,000, S = 49, I = 0.20)
| ช่วง | ราคา | Q* | Q ที่ใช้ | ค่าสินค้า | ค่าสั่งซื้อ | ค่าเก็บ | TC |
|---|---|---|---|---|---|---|---|
| 1 | 5.00 | 700 | 700 | 25,000 | 350 | 350 | 25,700 |
| 2 | 4.80 | 714 | 1,000 | 24,000 | 245 | 480 | **24,725** |
| 3 | 4.75 | 718 | 2,000 | 23,750 | 122.50 | 950 | 24,822.50 |

- `P_be(700) ≈ 4.8077`, `P_be(1000) = 4.80`, `P_be(2000) ≈ 4.7312`
- ข้อเสนอต่อรอง (714, 4.80): `TC_n ≈ 24,685.86` ประหยัด ≈ 39.14 ต่อปี

## 5. หน้าจอ

ภาษาบนหน้าจอเป็นไทย คงศัพท์วิชาเป็นอังกฤษ (EOQ, TC, Ordering cost, Holding cost)

```
┌──────────────────────────────────────────────────────────────────┐
│ QDM Negotiator                          [คัดลอกลิงก์] [รีเซ็ต]   │
├───────────────────┬──────────────────────────────────────────────┤
│ สมมติฐาน          │ ① ข้อเสนอปัจจุบันของร้าน (กราฟ TC ต่อ Q)     │
│ D, S, I           ├──────────────────────────────────────────────┤
│ ตารางส่วนลด       │ ② ราคาเท่าทุนของแต่ละขนาดล็อต (กราฟราคาต่อ Q)│
│ [+ เพิ่มช่วง]     ├──────────────────────────────────────────────┤
│                   │ ③ ข้อเสนอต่อรอง (ล็อตที่ขอ, ราคาที่ขอ, ผล)   │
├───────────────────┴──────────────────────────────────────────────┤
│ ④ ตารางเปรียบเทียบ: ทุกช่วงราคาของร้าน + ข้อเสนอต่อรอง           │
└──────────────────────────────────────────────────────────────────┘
```

### แผงสมมติฐาน (ซ้าย)
- `D`, `S`, `I`: แต่ละตัวมี slider และช่องตัวเลข ค่าทั้งสองผูกกัน
  ถ้าพิมพ์ค่าเกินช่วงของ slider ช่วงของ slider ขยายตาม
- ตารางส่วนลด: แก้ `minQty` และราคาของแต่ละช่วงได้ เพิ่มหรือลบช่วงได้
  ช่วงแรกล็อก `minQty = 0` และลบไม่ได้ จำกัดไม่เกิน 6 ช่วง
- การตรวจค่า: `D`, `S`, `I`, ราคา ต้องมากกว่า 0 และ `minQty` ต้องเป็นจำนวนเต็มที่เรียงจากน้อยไปมากโดยไม่ซ้ำ
  ถ้าค่าผิด แสดงข้อความเตือนใต้ช่องนั้น และคงผลลัพธ์ล่าสุดที่ถูกต้องไว้บนจอ

### ① กราฟ TC ต่อ Q
- แกนนอน Q แกนตั้ง TC ต่อปี แกนตั้งไม่เริ่มจาก 0 เพราะค่าสินค้ามีขนาดใหญ่กว่าส่วนอื่นมาก
  ให้ปรับช่วงแกนตั้งรอบบริเวณจุดต่ำสุด และตัดส่วนของเส้นที่พุ่งสูงตอน Q น้อย
- แต่ละช่วงราคา: เส้นทึบในช่วงปริมาณที่ซื้อได้จริง เส้นประจางนอกช่วง (แบบสไลด์ 53)
- จุด `Q*` ของแต่ละช่วง และจุดหลังปรับ จุดของข้อเสนอที่ดีที่สุดของร้านเน้นเด่น
- เส้นนอนที่ระดับ `TC_best`: จุดใดอยู่ใต้เส้นนี้ถือว่าดีกว่าข้อเสนอของร้าน
- เส้นประของข้อเสนอต่อรอง: `TC(Q, Pn)` ตลอดช่วง Q พร้อมจุด (Qn, TC_n) ที่ลากแนวนอนได้เพื่อเปลี่ยน `Qn`

### ② กราฟราคาเท่าทุน
- แกนนอน Q ช่วงเดียวกับกราฟ ① แกนตั้งเป็นราคาต่อหน่วย
- เส้นขั้นบันไดของราคาที่ร้านเสนอ และเส้นโค้ง `P_be(Q)`
- พื้นที่ใต้เส้น `P_be(Q)` ระบายสีและมีป้าย "ต่อรองได้ในโซนนี้ เราได้ประโยชน์"
- จุด (Qn, Pn) ของข้อเสนอต่อรอง ถ้าอยู่ใต้เส้นเท่าทุนแสดงเป็น "ได้ประโยชน์" ถ้าอยู่เหนือเส้นแสดงเป็น "แพงกว่าเดิม"
  สถานะต้องบอกด้วยข้อความหรือไอคอนด้วย ไม่ใช้สีอย่างเดียว

### ③ ข้อเสนอต่อรอง
- slider และช่องตัวเลขสำหรับ `Qn` และ `Pn` และปุ่ม "ใช้ค่าแนะนำ"
- ตัวเลขผลลัพธ์ขนาดใหญ่: TC ใหม่, เงินที่ประหยัดต่อปี, จำนวนครั้งที่สั่งต่อปี, สต็อกเฉลี่ย, ราคาเท่าทุนที่ล็อตนี้
- ประโยคสรุป 1 บรรทัดสำหรับพูดตอนนำเสนอ เช่น
  "ขอราคา ฿4.80 ที่ล็อต 714 ชิ้น โดยสัญญาซื้อรวม 5,000 ชิ้น/ปี: TC ลดจาก ฿24,725 เหลือ ฿24,686 และสต็อกเฉลี่ยลดจาก 500 เหลือ 357 ชิ้น"
  ถ้าข้อเสนอแพงกว่าเดิม ให้ประโยคบอกว่าแพงกว่าเท่าไร และต้องได้ราคาไม่เกินเท่าไรจึงคุ้ม

### ④ ตารางเปรียบเทียบ
- คอลัมน์แบบสไลด์ 52: ช่วง, ราคา, Q, ค่าสินค้า, ค่าสั่งซื้อ, ค่าเก็บรักษา, TC และเพิ่มคอลัมน์ส่วนต่างจาก `TC_best`
- แถวของแต่ละช่วงแสดงสถานะ (ใช้ได้, ปรับขึ้น, ตัดทิ้ง) แถวที่ดีที่สุดเน้นเด่น
- แถวสุดท้ายคือข้อเสนอต่อรอง

### ส่วนหัว
- "คัดลอกลิงก์": คัดลอก URL ปัจจุบันซึ่งมีค่าทั้งหมดอยู่ในนั้น
- "รีเซ็ต": กลับไปเป็นโจทย์ Bee Beauty และค่าแนะนำของข้อเสนอต่อรอง

## 6. รูปแบบภาพ
- ธีมพื้นสว่าง การ์ดมุมโค้ง ระยะห่างกว้าง ใช้ CSS variables สำหรับสีและระยะ
- ฟอนต์ IBM Plex Sans Thai จาก Google Fonts และ fallback เป็นฟอนต์ของระบบ ตัวเลขใช้ `font-variant-numeric: tabular-nums`
- ขนาดตัวอักษรพื้นฐาน 16–18px ตัวเลขผลลัพธ์หลัก 28–32px เพื่อให้อ่านได้เมื่อฉาย
- สีของแต่ละช่วงราคาคงที่ทั้งกราฟและตาราง ข้อเสนอต่อรองใช้สีเฉพาะที่ต่างจากทุกช่วง
- Layout ด้วย CSS grid: แผงซ้ายกว้างประมาณ 320px ติดอยู่กับที่เมื่อเลื่อนหน้า
  จอกว้างต่ำกว่า 900px เรียงเป็นคอลัมน์เดียว
- กราฟวาดใหม่ทุกครั้งที่ input เปลี่ยน ภายใน `requestAnimationFrame` ไม่ใช้ไลบรารี animation
  ถ้ามี transition ต้องปิดเมื่อผู้ใช้ตั้ง `prefers-reduced-motion`

## 7. การเข้าถึง
- input ทุกตัวมี label ใช้คีย์บอร์ดได้ทั้งหมด slider `Qn` เป็นทางเลือกแทนการลากจุดบนกราฟ
- ข้อความเตือนผูกกับช่องด้วย `aria-describedby`
- กราฟ SVG มี `role="img"` และ `aria-label` ที่สรุปผล บริเวณผลลัพธ์เป็น `aria-live="polite"`
- สีผ่านเกณฑ์ contrast ระดับ AA


- ไฟล์ JavaScript เป็น ES modules โหลดด้วย `<script type="module">`
  การเปิดดูในเครื่องจึงต้องผ่าน static server เช่น `python -m http.server` เปิดไฟล์ตรง ๆ แบบ `file://` ไม่ได้
- ทิศทางข้อมูล: input → state → `model.js` คำนวณ → `charts.js` และส่วนผลลัพธ์แสดงผล → เขียน state ลง URL

### ค่าใน URL
- เก็บใน hash เช่น `#d=5000&s=49&i=20&t=0:5,1000:4.8,2000:4.75&q=714&p=4.8`
- อัปเดตด้วย `history.replaceState` เพื่อไม่ให้ประวัติเบราว์เซอร์ยาว
- ถ้า hash ไม่มี หรือค่าใดอ่านไม่ได้หรือไม่ผ่านการตรวจ ใช้ค่าเริ่มต้นของค่านั้น

## 9. การทดสอบ
- `tests/model.test.js` (รันด้วย `node --test`):
  - ตัวเลขทุกค่าในตารางอ้างอิงของหัวข้อ 4 รวมถึงสถานะ feasible / adjusted และช่วงที่ดีที่สุด
  - `P_be` ที่ Q = 700, 1,000, 2,000 และข้อเสนอต่อรอง (714, 4.80)
  - กรณีช่วงเดียวจากรูป EOQ: D = 4,750, S = 150, ราคา 60, I = 0.20 (H = 12) ได้ Q* = 345 และค่าสั่งซื้อ ≈ ค่าเก็บรักษา ≈ 2,068
  - กรณี `discarded`: ช่วงที่ `Q*` สูงกว่าขอบบน ต้องไม่ถูกเลือกเป็นช่วงที่ดีที่สุด

- ตรวจหน้าจอด้วยมือในเบราว์เซอร์: เลื่อน slider ทุกตัว แก้ตารางส่วนลด ลากจุดบนกราฟ คัดลอกลิงก์แล้วเปิดในแท็บใหม่ และเทียบค่าเริ่มต้นกับสไลด์
